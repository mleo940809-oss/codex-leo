# Review and Freeze Gates

## Review gates

- Review must end with a clear decision: approved, conditionally approved, or rejected.
- A review without a decision is incomplete.
- Conflicting opinions must be resolved or explicitly escalated.

## Freeze gates

- Scope, core flow, rules, exceptions, fields, and acceptance criteria must be settled.
- Open disputes must be closed before freeze.
- Anything not validated or not decided should be marked clearly as pending, not implied as final.

## Quality checks

- Every functional item should be traceable to a user story, page, rule, exception, and test point.
- Rules should be unambiguous and executable.
- Missing owners, missing approvals, or untestable criteria block progression.
