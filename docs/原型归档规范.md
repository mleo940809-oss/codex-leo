# 原型归档规范

> 适用范围：正式 PRD、正式原型、高保真原型、交付原型的冻结后留档。  
> 目标：让原型具备可追溯、可回读、可审计、可恢复的最小闭环。

## 1. 归档原则

1. 原型必须先冻结，再归档。
2. 原型必须与对应 PRD 冻结版本一一对应。
3. 当前绑定和历史归档分开管理。
4. 临时预览稿、演示稿不进入正式归档。

## 2. 固定路径

正式原型只使用以下路径：

```text
docs/prototype/<文档名>/binding.md
docs/prototype/<文档名>/archive/<文档名>_v<版本号>_<YYYYMMDD>/
```

- `binding.md`：当前正式绑定记录，只保留一份。
- `archive/`：冻结后的历史归档目录，每次正式冻结新增一版。
- `render_current/`：仅用于临时渲染和预览，不视为正式留档。

## 3. 归档内容

每次正式归档至少保留：

- `archive-manifest.md`
- 原型活链接
- 对应 PRD 冻结版本
- 原型版本号或页面范围
- 源文件路径
- 关键页面预览图或导出图
- 归档确认人和归档时间

## 4. 绑定规则

1. 正式原型先写 `binding.md`，再生成归档目录。
2. `binding.md` 负责当前正式绑定，不替代历史归档。
3. `archive/` 负责冻结后留痕，不替代当前绑定。
4. 两者必须可互相追溯，但不能互相覆盖。

## 5. 更新规则

1. 每次正式冻结都必须生成新的归档目录。
2. 归档目录一经生成不得覆盖旧版本。
3. 正式原型、`binding.md`、归档目录必须同轮进入 Git 历史。
4. 如果原型改动影响页面、状态、交互或权限，必须先更新 PRD，再更新原型归档。

## 6. 禁止事项

- 禁止把临时预览稿当正式归档。
- 禁止只留截图而没有源文件路径。
- 禁止没有 `binding.md` 就直接归档。
- 禁止冻结后覆盖旧归档目录。
- 禁止让原型归档脱离对应 PRD 版本。

## 7. 最小检查清单

归档前必须确认：

- 原型活链接可打开
- 对应 PRD 版本已冻结
- `binding.md` 已更新
- 归档目录已生成
- 源文件路径已记录
- 预览图或导出图已留存
- 归档人和时间已记录
