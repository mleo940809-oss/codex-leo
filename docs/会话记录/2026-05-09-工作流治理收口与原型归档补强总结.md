# 会话记录：工作流治理收口与原型归档补强总结

**日期**：2026-05-09  
**主题**：工作流总入口、正式 PRD 模板、原型绑定与归档、`.docx` 链路、技能路由补齐

## 当前目标

把 `E:\Codex\New_rules` 的工作流继续收口为一套可导航、可执行、可追溯、可长期维护的体系，并补齐 PRD 与原型之间的强一致性门禁、正式原型的绑定/归档层，以及对应的执行技能路由。

## 本次会话的主要结论

1. 工作流已经形成统一入口：
   - `AGENTS.md`
   - `docs/工作流总入口.md`
   - `docs/docx产物链路说明.md`
   - `docs/原型归档规范.md`

   - 前期探索：`PRD工作流复用模板.md`
   - 正式交付：`standard-prd-template.md`

   - `PRD-原型一致性矩阵`
   - `原型绑定记录`
   - `原型归档记录`

4. 原型治理已补齐两个层次：
   - `binding.md`：当前正式绑定记录
   - `archive/`：冻结后的长期留痕目录

5. `.docx` 链路已经与原型治理对齐：
   - 正式 `.docx` 生成前必须先满足 PRD / 原型相关门禁
   - 正式 `.docx`、`binding.md`、原型归档目录需同轮进入 Git 历史

6. PRD 细粒度子章节的技能路由已补齐：
   - `2.1.1.6.1` 功能逻辑说明
   - `2.1.1.6.2` 交互说明
   - `2.1.1.6.3` 字段说明
   - `2.1.1.6.4` 业务规则
   - `2.1.1.7` 异常情况

## 已确认的工作流结构

1. 总入口只负责导航，不参与规则仲裁。
2. 权威规范负责正文规则。
3. Markdown 是正文源。
4. 正式原型必须有：
   - `binding.md`
   - `archive/` 归档层
5. 正式 `.docx` 必须有独立绑定记录。
6. 版本快照继续使用分层目录：
   - `docs/versions/<文档名>/<文档名>_v<版本号>_<YYYYMMDD>.md`

## 本次会话中达成的约束

1. `PRD-原型一致性矩阵` 必须在正式模板中显式出现。
2. 正式原型必须有 `docs/prototype/<文档名>/binding.md`。
3. 正式原型冻结后必须有 `docs/prototype/<文档名>/archive/<文档名>_v<版本号>_<YYYYMMDD>/`。
4. `binding.md` 与 `archive/` 不能互相替代。
5. 原型治理、`.docx` 链路和 Git 留档必须同轮闭合。
6. PRD 子章节的技能路由不能只靠上级继承，必须显式列出。

## 剩余风险

1. 现在同一组前置条件的说法已经统一为“5 项冻结前检查”，后续新增条目时要继续沿用这个口径，不要回退成“4 个门禁”。
2. 原型可交互性已经能在流程上验证，但还依赖外部原型链接长期可访问，仍需注意权限和链接有效性。
3. 正式 PRD 7 章已经承载较多交付约束，后续应避免继续往里塞新的规则源。

## 下一步建议

1. 保持前期探索模板和正式模板严格分离。
2. 新增或冻结原型时，优先走 `原型归档规范.md`。
3. 若再新增规则，优先判断是否应该独立成文，不要回塞主模板。
4. 继续保持 `.docx`、原型绑定、原型归档和快照目录的单一口径。
