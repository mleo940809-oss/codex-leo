## 活动列表页已确认内容

1. 列表页是活动总入口。
2. 顶部按钮只有 `新增活动`。
3. 行内按钮包括：
   - 查看
   - 编辑
   - 修改
   - 批次管理
   - 失效
4. 查询条件包括：
   - 商品券名称
   - 商品券ID
   - 商品券类型
   - 优惠范围
   - 状态
   - 创建人
   - 最后修改人
   - 创建时间
   - 最后修改时间
   - 活动使用时间范围
5. `使用模式` 和 `券Code分配模式` 不作为查询条件。
6. `活动使用时间范围` 用于查找与查询时间范围存在**部分重叠**的活动。
7. `活动使用时间范围` 的展示值取活动下所有**非草稿批次**的最早可用开始时间和最晚可用结束时间。
8. `活动使用时间范围` 的查询规则采用区间重叠判断，且**草稿批次不参与查询**。
9. `批次管理` 在 `AUDITING` 状态下允许进入，但只允许查看和预配置。
10. `EFFECTIVE` 状态下可以完整管理批次。
11. `DEACTIVATED` 状态下批次管理不可用。
12. `编辑` 仅在 `草稿`、`审批中` 可用。
13. `修改` 仅在 `生效中` 可用。
14. `失效` 仅在 `生效中` 可用。

## 活动新增页已确认内容

1. 采用两段式流程：
   - 第一步先选券类型
   - 第二步进入对应表单
2. 券类型不能中途切换。
3. 返回券类型选择页时不保留已填内容。
4. 允许保存草稿。
5. 同一活动同一时间只能有一个草稿。
6. `Code 文件上传` 不在新增页，统一放到批次管理页。
7. 新增页结构定为：
   - 公共区
   - 差异区
   - 提交确认
8. 所有字段都用中文字段名，不展示接口参数名。
9. 每个字段都补了输入规则、提示文案、金额小数位、图片规格、字符长度和联动关系。
10. `提交审核` 成功后返回活动详情页。
11. 不保留“可选按钮”作为主版本内容。
12. 公共区、差异区、按钮规则、字段输入规则、提示文案与联动关系都已在新增页完整展开，不再使用“引用新增页”之类的替代性写法。

## 活动编辑页已确认内容

1. 编辑页只处理草稿核对和 `AUDITING` 前的生效前修订。
2. `EFFECTIVE` 和 `DEACTIVATED` 不使用本页。
3. `Code` 配置不放编辑页，统一放批次管理页。
4. 编辑页最终结构为：
   - 基础信息
   - 公共字段区
   - 满减券差异区
   - 兑换券差异区
   - 编辑确认
5. 编辑页中的同名字段规则必须完整展开，不再写“引用新增页”。
6. 编辑页当前已删除无依据的字段：
   - 活动有效期
   - 优惠范围
   - 活动说明
   - 发放方式
   - 生效规则
   - Code 配置
7. 编辑页保留：
   - 商品券名称
   - 商品券图片
   - 商品券背景图
   - 商品券详情图
   - 商品券标题文案
   - 商品券副标题
   - 规则摘要
   - 使用模式
   - 满减券字段
   - 兑换券字段
8. 按钮主版本只保留：
   - 保存修改
   - 取消

1. 已读取活动修改页初始稿。
2. 已判断当前修改页不能直接无脑复用新增页字段规则。
3. 当前核心未决点：
   - 活动修改页到底是只改展示信息，还是也允许改券规则字段
4. 当前已接受的专业建议方向：
   - 修改页可编辑低风险字段，高风险字段只读展示
   - `Code 配置` 不应放在修改页
   - `活动有效期`、`发放方式`、`生效规则` 这类字段需要先确认业务和接口边界
5. 修改页尚未完成最终收口，仍在持续评审中。

## 已确认的流程治理规则

1. 每个独立需求都要有自己的目录。
2. 需求目录下要统一管理该需求的正式产物。
3. 历史版本必须与当前最新版本分离管理。
4. 产物管理规则已同步到流程、提交、入口和治理文档。
5. 需求进入流程后，正式产物目录治理要显式遵循 `工作产出物管理规则.md`。

## 本次新增确认的时间口径

1. 活动列表页新增了 `活动使用时间范围` 筛选条件。
2. 该条件用于查找与查询时间范围存在**部分重叠**的活动。
3. 活动使用时间范围的展示值取该活动下所有**非草稿批次**的最早可用开始时间和最晚可用结束时间。
4. 草稿批次不参与该条件的查询与汇总。
5. 区间重叠的判断规则为：
   - 批次可用开始时间 `<=` 查询结束时间
   - 且批次可用结束时间 `>=` 查询开始时间

## 剩余风险

1. 活动修改页的范围仍未最终收口。
2. 修改页是否允许修改券规则字段，尚未最终冻结。
3. 批次管理页虽然已收口，但后续仍可继续细化字段级规则与接口映射。
4. 后续继续扩展页面时，要坚持“字段规则完整展开，不用引用替代正文”的口径。

## 下一步建议

1. 继续收口活动修改页的业务边界。
2. 如进入正式 PRD 汇总阶段，再把各页面内容合并到正式模板。
3. 后续页面补充时，继续坚持目录分层和版本归档规则。
4. 若要继续优化列表页，可再围绕列宽、排序、空态、筛选默认值做二次收敛。
