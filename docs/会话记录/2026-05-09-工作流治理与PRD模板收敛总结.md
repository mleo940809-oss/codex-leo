# 会话记录：工作流治理与 PRD 模板收敛总结

**日期**：2026-05-09  
**主题**：工作流治理、PRD 模板分阶段输出、原型归档规范收敛

## 当前目标

把 PRD 工作流、模板、技能路由、版本快照、原型归档和 Git 提交链路收束成一套可执行、可回读、可审计的规范体系。

## 已确认事项

1. PRD 模板分为两阶段：
   - 前期探索：`PRD工作流复用模板.md`
   - 正式交付：`standard-prd-template.md`
2. `standard-prd-template.md` 的关键章节必须以图形化方式输出，且每张图都要有可编辑源文件。
3. PRD 功能拆解必须写到页面级，`2.1` 为一级模块，`2.1.1 / 2.1.2` 为页面级功能点，`2.1.1.1` 起为页面细节。
4. 新增独立的 `原型归档规范.md`，用于正式原型的绑定与归档。
5. 原型正式归档路径固定为：
   - `docs/prototype/<文档名>/binding.md`
   - `docs/prototype/<文档名>/archive/<文档名>_v<版本号>_<YYYYMMDD>/`
6. 原型归档规范已纳入以下入口：
   - `AGENTS.md`
   - `工作流总入口.md`
   - `standard-prd-template.md`
   - `产品需求管理流程规范.md`
   - `流程执行技能附录.md`
7. 快照目录口径已统一为分层目录：
   - `docs/versions/<文档名>/<文档名>_v<版本号>_<YYYYMMDD>.md`
8. 本地与远端 Git 已同步，当前 `main` 与 `origin/main` 一致。

## 已做决定

1. 原型归档不再混入 PRD 主模板正文，改为独立短规范。
2. 总入口只做导航，不做规则仲裁。
3. `.docx`、原型绑定、原型归档分别走各自唯一正式载体，不再多载体并行。
4. 正式 PRD 输出时必须使用 `standard-prd-template.md`。

## 待办事项

1. 如果后续继续强化原型治理，可再把 `原型归档规范.md` 的条款版压缩成对外发布版。
2. 如需进一步统一前端原型输出链路，可补充 `.docx` / Figma / HTML 原型的执行细则。

## 风险与限制

1. 当前工作区仍存在一批历史迁移痕迹和旧版本快照文件，需要后续分批清理。
2. PRD 模板、流程规范、技能附录之间已建立引用，但后续仍需防止新增规则再次变成“总汇编”。
3. 本次会话记录为本地文件；若需要团队协作，建议同步到正式知识库。

## 下一步动作

1. 继续保持 PRD 模板按“前期探索 / 正式交付”双阶段使用。
2. 原型新增或冻结时，按 `原型归档规范.md` 处理绑定和归档。
3. 若后续有新规则，先判断是否应该成为独立规范，避免塞回主模板。
