# 会话记忆强制执行规则

> 适用范围：本工作区内所有需要跨会话延续的对话、分析、决策、需求和任务协作。
> 规则优先级：本规则高于临时习惯、口头约定和“先聊完再说”的默认处理方式。

## 1. 目标

确保任何会话在进入背景信息压缩、上下文衰减或新会话接续之前，已经被整理为可长期回读、可定位、可更新的单一记录，避免关键信息只存在于短期上下文中。
每次执行会话总结时，都必须产出一份对应的会话记录文档，不能只停留在聊天总结里。

## 2. 执行层级

### 2.1 核心强制

1. 禁止只在会话结束时才总结。
2. 只要出现压缩前兆，必须先总结，再继续推进当前会话。
3. 每个会话必须对应一个唯一的会话记录，不得把同一会话的核心内容拆散到多个互不关联的记录中。
4. 会话记录必须持续更新，不得只做一次性归档后不再维护。
5. 每次形成新的关键结论、决定、待办、风险或未决问题时，都要同步写入会话记录。
6. 每次执行会话总结时，都必须产出一份对应的会话记录文档，不得只在聊天窗口内完成总结。
7. 执行这类会话记忆沉淀工作时，必须优先使用 `notion-knowledge-capture`。
8. 当需要定义、变更或强化这类行为规则时，必须先按 `superpowers:brainstorming` 的流程完成设计确认，再进入落地。

### 2.2 默认执行

1. 新开会话时，应先读取 `docs/工作流总入口.md`、总索引和最近相关会话记录，再开始处理新问题。
2. `docs/工作流总入口.md` 只负责导航，不替代会话记录，也不参与会话记忆规则仲裁。

### 2.3 条件强制

1. 当任务涉及跨会话延续、决策型问题、上下文冲突、长任务接续或明显压缩风险时，必须先完成历史读取，再给出结论、建议、判断或方案。
2. 如果压缩前时间不足，先写最小可恢复摘要，再补充细节，不得带着不可恢复的信息进入压缩。

## 3. 触发条件

满足任一条件时，立即执行会话总结：

- 背景剩余空间预计已降至 35% 或更低
- 背景信息窗口明显缩小，已经接近自动压缩风险
- 系统提示背景信息将被压缩或已开始压缩
- 当前会话内容已出现较多主题切换，后续回忆成本明显上升
- 关键决策已经形成，但尚未落到可检索的记录中
- 当前会话预计还会继续，但上下文保留风险已高于可接受阈值

## 4. 必须落地的内容

每个会话记录至少包含以下内容：

- 会话主题
- 会话日期
- 当前目标
- 已确认事项
- 已做决定
- 待办事项
- 风险与限制
- 未决问题
- 下一步动作
- 相关会话或相关主题的引用入口

## 5. 执行顺序

1. 发现压缩前兆，或识别出需要延续历史的任务。
2. 判断是否属于条件强制场景。
3. 读取总索引和相关历史记录。
4. 汇总当前会话的关键结论和上下文。
5. 写入当前会话记录。
6. 更新总索引。
7. 再继续后续讨论或收尾。

## 6. 验收标准

只有同时满足以下条件，才算执行到位：

- 当前会话的核心内容可以在单一记录中回读
- 新开会话可以通过总索引快速定位到相关历史内容
- 关键决策不会因为上下文压缩而丢失
- 会话推进过程中形成的新结论能够被持续追踪

## 7. 失败处理

如果发现会话已经进入压缩阶段但还没有完成总结，必须优先补写最小可恢复摘要，再继续后续工作。不得以“稍后再整理”为理由跳过记录。
