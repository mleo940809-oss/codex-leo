## 流程清单

| 序号 | 流程名称 | 类型 | 说明 |
|---:|---|---|---|
| 1 | 商品券业务总生命周期 | 业务主流程 | 从接入授权到终态管理 |
| 2 | 品牌接入与授权准备 | 操作子流程 | 服务商完成基础接入与回调配置 |
| 3 | 商品券创建流程 | 操作子流程 | 定义券规则并创建券主对象 |
| 4 | 批次创建与投放规则配置 | 操作子流程 | 建立可投放、可审核的批次 |
| 5 | 发券渠道派发流程 | 业务主流程 | 微信营销渠道 / 服务商主动发券两条路径 |
| 6 | 回调接收与发放确认 | 状态流转图 | 服务商接收微信回调并确认发放结果 |
| 7 | 领券后进入可用状态 | 状态流转图 | 从待确认 / 待生效到可用 |
| 8 | 用券与核销流程 | 操作子流程 | 门店或履约系统完成真实核销 |
| 9 | 退券与逆向履约流程 | 操作子流程 | 退款、取消履约等场景下的退券 |
| 10 | 失效、过期、删除终态 | 状态流转图 | 各类终态收口 |

## 1. 商品券业务总生命周期

```mermaid
flowchart TD
    A([开始]) --> B[品牌方接入并完成授权准备]
    B --> C[服务商配置商品券事件通知地址]
    C --> D[创建商品券母体]
    D --> E[创建批次并配置投放规则]
    E --> F{批次审核是否通过}
    F -->|通过| G[进入正式投放准备态]
    F -->|驳回| D
    G --> H{选择发券渠道}
    H -->|微信营销渠道| I[微信侧触发发券]
    H -->|服务商主动发券| J[服务商 API 直发]
    I --> K[微信向服务商发送商家券回调通知]
    J --> K
    K --> L{服务商是否确认成功}
    L -->|未到可用开始时间| M[PENDING 待生效]
    L -->|已到可用开始时间| N[EFFECTIVE 可用]
    M --> N
    N --> O[用户领券后使用]
    O --> P[门店或履约系统核销]
    P --> Q{是否发生退款或逆向履约}
    Q -->|是| R[退券回到 EFFECTIVE]
    Q -->|否| S[USED 已使用]
    S --> T{是否触发失效 / 过期 / 删除}
    T -->|是| U[终态收口]
    T -->|否| S
    R --> O
```

## 2. 品牌接入与授权准备

```mermaid
flowchart TD
    A([品牌方]) --> B[选择服务商]
    B --> C[完成服务商接入授权]
    C --> D[配置商家券事件通知地址]
    D --> E[准备 appid / brand_id / 证书等参数]
    E --> F[服务商侧完成回调验签与接收能力配置]
    F --> G([进入商品券创建阶段])
```

## 3. 商品券创建流程

```mermaid
flowchart TD
    A([开始创建商品券]) --> B[定义券类型、使用规则、适用范围]
    B --> C[填写名称、图文、基础展示信息]
    C --> D[服务商调用创建商品券接口]
    D --> E{微信审核是否通过}
    E -->|通过| F[商品券进入可用状态]
    E -->|驳回| G[修改商品券信息]
    G --> D
```

```mermaid
flowchart TD
    A([商品券创建完成]) --> B[创建批次]
    B --> C[配置发放预算]
    C --> D[配置每人限领]

    I --> J{审核结果}
    J -->|通过| K[SENDING 或正式可投放状态]
```

## 6. 回调接收与发放确认

```mermaid
flowchart TD
    A([服务商收到回调]) --> B[验签]
    B --> C[校验回调内容与本地业务一致性]
    C --> D{是否重复通知}
    D -->|是| E[幂等处理]
    D -->|否| F[记录发放结果]
    E --> F
    F --> G{可用开始时间是否已到}
    G -->|未到| H[PENDING 待生效]
    G -->|已到| I[EFFECTIVE 可用]
```

## 7. 领券后进入可用状态

```mermaid
stateDiagram-v2
    [*] --> 待确认
    待确认 --> PENDING: 已收到发券但未到可用时间
    待确认 --> EFFECTIVE: 已到可用开始时间
    PENDING --> EFFECTIVE: 到达可用开始时间
    EFFECTIVE --> [*]: 进入可使用链路
```

## 8. 用券与核销流程

```mermaid
flowchart TD
    A([用户到店 / 下单 / 履约]) --> B[门店或履约系统校验商家券]
    B --> C{是否满足使用条件}
    C -->|否| D[返回不可用原因]
    C -->|是| E[调用核销接口]
    E --> F{核销是否成功}
    F -->|成功| G[用户券状态变为 USED]
    F -->|失败| H[提示重试或重新校验]
```

## 9. 退券与逆向履约流程

```mermaid
flowchart TD
    A([已核销 / 已使用券]) --> B{是否发生退款、取消履约或逆向场景}
    B -->|是| C[服务商调用退券接口]
    C --> D[与原核销记录逐一匹配]
    D --> E[回退券状态到 EFFECTIVE]
    B -->|否| F[保持 USED]
```

## 10. 失效、过期、删除终态

```mermaid
stateDiagram-v2
    [*] --> EFFECTIVE
    EFFECTIVE --> USED: 核销成功
    EFFECTIVE --> EXPIRED: 超过有效期
    EFFECTIVE --> DEACTIVATED: 品牌方主动失效
    EFFECTIVE --> DELETED: 用户主动删除
    USED --> DEACTIVATED: 品牌方主动失效
    USED --> EXPIRED: 超过有效期
    USED --> DELETED: 用户主动删除
    EXPIRED --> [*]
    DEACTIVATED --> [*]
    DELETED --> [*]
```

## 关键决策点

| 决策点 | 判断条件 | 条件为真 | 条件为假 |
|---|---|---|---|
| 是否需要审核 | 商品券或批次是否进入正式发布链路 | 进入审核流程 | 直接保存或继续配置 |
| 是否进入可用 | 发放确认成功且可用时间已到 | 进入 EFFECTIVE | 进入 PENDING |
| 是否已核销 | 门店 / 履约系统完成真实核销 | 进入 USED | 保持原状态 |
| 是否允许退券 | 发生退款、取消履约或逆向处理 | 回退到 EFFECTIVE | 保持 USED |
| 是否终态 | 失效、过期或删除 | 进入终态 | 继续业务流转 |
