# 文档仓库提交规范

## 1. 目标

本规范用于 `E:\Codex\New_rules` 这类以制度、流程、PRD 和版本快照为主的文档仓库。目标是让每次修改都具备：

- 可追溯
- 可回滚
- 可审阅
- 可对比

## 2. 分支策略

- `main` 只保留稳定、可对外使用的版本
- 每次文档修改先建分支，再修改正文
- 分支命名建议：
  - `docs/<主题>`
  - `fix/<问题>`
  - `review/<轮次>`

示例：

```powershell
git switch -c docs/prd-workflow-update
```

## 3. 文件放置规则

- 当前生效正文放在主文档路径
- 历史版本放在 `docs/versions/`
- 临时渲染结果放在 `render_current/`
- 草稿、截图、分析过程不要混进正式交付目录

## 4. 提交前检查

提交前必须先确认：

- 这次改动是不是同一主题
- 是否误改了无关文件
- 是否包含临时文件或生成物
- 版本快照是否已经留存

推荐检查命令：

```powershell
git status
git diff
```

## 5. 暂存原则

- 能精确指定文件时，优先按文件暂存
- 只有在确认本次所有改动都要提交时，才使用 `git add .`
- 不要把无法解释的杂项文件一起提交

示例：

```powershell
git add docs/产品需求管理流程规范.md
git add docs/versions/产品需求管理流程规范_v1.6_20260509.md
```

## 6. 提交信息规范

提交信息要短、明确、可检索。推荐格式：

- `docs: update prd workflow`
- `docs: add review checklist`
- `docs: refresh version snapshot`
- `chore: update git rules`

要求：

- 说明这次提交做了什么
- 不要只写 `update`、`fix` 这种空泛词
- 一个提交尽量只表达一类变更

## 7. 版本管理规则

- 正式改动前先保留版本快照
- 历史版本只追加，不覆盖
- 版本号递增后，不回写旧稿
- 版本文件命名要包含主题、版本号和日期

推荐命名示例：

```text
docs/versions/产品需求管理流程规范_v1.6_20260509.md
```

## 8. 常用命令

```powershell
git switch -c docs/prd-update-20260509
git status
git diff
git add docs/产品需求管理流程规范.md
git commit -m "docs: update prd workflow"
git log --oneline --decorate -5
```

## 9. 回滚原则

- 撤回单个文件时优先使用 `git restore`
- 不要轻易使用整仓库重置
- 真正需要回退时，先确认影响范围，再执行回滚

示例：

```powershell
git restore docs/产品需求管理流程规范.md
```

## 10. 审阅规则

- 改正文档前，先判断本次变更是否会影响流程口径
- 涉及 PRD、流程、制度时，优先检查完整性、可执行性和可测试性
- 审阅通过前，不要把半成品当最终版提交

## 11. 严格版本号规则

### 11.1 版本号结构

正式文档版本号统一采用以下结构：

```text
主版本.次版本.日期.修订序号
```

示例：

```text
v1.4.20260509.01
v1.4.20260509.02
v1.5.20260510.01
```

### 11.2 递增原则

- 主版本升级：流程或规则有结构性变化时使用
- 次版本升级：同一流程内出现较大调整时使用
- 日期字段：必须与实际修改日期一致
- 修订序号：同一天同一版本下按 `01、02、03` 递增

### 11.3 禁止行为

- 不得跳号
- 不得同名覆盖旧版本
- 不得把草稿直接命名为正式版本
- 不得在版本号里混入模糊词，例如“最终版”“新版”“优化版”

### 11.4 文件命名示例

```text
docs/versions/产品需求管理流程规范_v1.5.20260509.01.md
docs/versions/产品需求管理流程规范_v1.5.20260509.02_review.md
docs/versions/产品需求管理流程规范_v1.6.20260510.01.md
```

### 11.5 提交配套规则

- 每次正式修订必须先生成对应版本快照
- 正文文件与版本快照应保持内容一致
- 如果同一天反复修改，先在版本号中递增修订序号，再提交
