# Weixin摇一摇 - 批次管理页设计稿

**文档版本**：V1.1  
**创建日期**：2026-05-10  
**适用范围**：Weixin摇一摇需求目录下的批次管理页  
**文档性质**：修订版，明确批次本体字段、状态机和 Code 管理边界

## 1. 设计目标

批次管理页用于管理单个商品券活动下的批次信息，承载批次的创建、查看、预配置、Code 管理、发放控制和状态管理。

本页只描述批次管理的页面能力，不展开后端接口实现细节。后端接口流转、异步回调和生命周期控制放入概设和流程图中体现。

## 2. 已确认的业务前提

1. 批次归属于某一个活动，不能脱离活动独立存在。
2. `AUDITING` 状态下允许进入批次管理页，但仅支持查看和预配置。
3. `EFFECTIVE` 状态下允许完整批次管理。
4. `DEACTIVATED` 状态下不允许批次管理。
5. 预配置不等于发放，不触发任何券生命周期动作。
6. `Code` 文件上传归属批次管理页，不归属活动新增页、编辑页或修改页。

## 3. 页面定位

- 一级模块：Weixin摇一摇
- 二级页面：批次管理页
- 页面职责：
  - 查看活动下的批次列表
  - 新建批次草稿
  - 维护批次基础信息
  - 预上传 Code 并校验
  - 控制批次发放状态
  - 查看批次操作记录

## 4. 页面结构

建议批次管理页采用“活动摘要 + 批次列表 + 批次详情抽屉/面板 + Code 管理区 + 操作记录区”的结构：

1. 活动摘要区
2. 批次列表区
3. 批次详情区
4. Code 管理区
5. 操作记录区

## 5. 字段设计

### 5.1 活动摘要区

活动摘要区用于展示当前活动的关键信息，便于批次操作时确认上下文。

| 字段 | 说明 | 展示方式 | 备注 |
|---|---|---|---|
| 商品券名称 | 当前活动名称 | 只读文本 | 用于确认活动上下文 |
| 商品券ID | 当前活动唯一标识 | 只读文本 | 用于定位活动 |
| 商品券类型 | 满减券 / 兑换券 | 只读文本 | 仅展示当前活动类型 |
| 活动状态 | 当前活动状态 | 状态标签 | 用于判断是否允许操作 |
| 优惠规则摘要 | 当前活动规则概述 | 只读文本 | 便于快速识别活动内容 |

### 5.2 批次列表区

批次列表区用于展示当前活动下的批次集合。

| 字段 | 说明 | 展示方式 | 备注 |
|---|---|---|---|
| 批次编号 | 批次唯一标识 | 只读文本 | 系统生成 |
| 批次名称 | 批次展示名称 | 只读文本 | 支持快速识别 |
| 批次状态 | 当前批次状态 | 状态标签 | 与状态机绑定 |
| 预计开始时间 | 计划发放开始时间 | 时间文本 | 若未配置则显示空态 |
| 预计结束时间 | 计划发放结束时间 | 时间文本 | 若未配置则显示空态 |
| Code 总量 | 当前批次 Code 总数 | 数值 | 用于库存展示 |
| 已使用量 | 已发放或已消耗数量 | 数值 | 用于统计展示 |
| 剩余量 | 当前可用 Code 数量 | 数值 | 用于库存展示 |
| 创建人 | 批次创建人 | 只读文本 | 支持检索 |
| 最后修改人 | 最近一次修改批次的人 | 只读文本 | 支持检索 |
| 操作 | 批次行内操作 | 按钮组 | 按状态控制 |

### 5.3 批次详情区

批次详情区用于展示和维护单个批次的完整信息。

#### 5.3.1 批次基础信息

| 字段 | 说明 | 是否可编辑 | 类型 | 备注 |
|---|---|---:|---|---|
| 批次名称 | 批次展示名称 | 是 | 文本 | 允许在可编辑状态下修改 |
| 批次编号 | 批次唯一标识 | 否 | 只读文本 | 系统生成 |
| 关联活动 | 所属活动 | 否 | 只读文本 | 与当前活动绑定 |
| 批次状态 | 当前批次状态 | 否 | 状态标签 | 由状态机驱动 |
| 预计开始时间 | 计划发放开始时间 | 是 | 时间选择 | 仅在允许编辑时修改 |
| 预计结束时间 | 计划发放结束时间 | 是 | 时间选择 | 仅在允许编辑时修改 |
| 适用范围 | 批次适用范围 | 是 | 下拉/配置项 | 根据活动规则约束 |
| 批次说明 | 批次补充说明 | 是 | 多行文本 | 支持补充业务说明 |

#### 5.3.2 批次统计信息

| 字段 | 说明 | 展示方式 | 备注 |
|---|---|---|---|
| Code 总量 | 批次 Code 总数 | 数值 | 只读展示 |
| 已使用量 | 已发放或已消耗数量 | 数值 | 只读展示 |
| 剩余量 | 当前可用 Code 数量 | 数值 | 只读展示 |
| 发放成功量 | 发放成功数量 | 数值 | 只读展示 |
| 发放失败量 | 发放失败数量 | 数值 | 只读展示 |

### 5.4 Code 管理区

Code 管理区用于上传和校验批次待用 Code。

| 字段 | 说明 | 展示方式 | 备注 |
|---|---|---|---|
| Code 上传状态 | 当前 Code 文件处理状态 | 状态标签 | 如未上传、处理中、已校验、校验失败 |
| Code 文件名 | 已上传文件名 | 只读文本 | 用于识别文件 |
| Code 校验结果 | 文件合法性校验结果 | 结果标签 | 保存前需确认 |
| 上传时间 | 文件上传时间 | 时间文本 | 只读展示 |
| 校验时间 | 文件校验时间 | 时间文本 | 只读展示 |

## 6. 按钮设计

### 6.1 顶部按钮

| 按钮 | 作用 | 适用状态 | 说明 |
|---|---|---|---|
| 新建批次 | 创建新的批次草稿 | `AUDITING`、`EFFECTIVE` | `AUDITING` 仅允许草稿和预配置 |
| 返回活动详情 | 返回活动详情页 | 全部状态 | 回到上级页面 |

### 6.2 批次列表行内按钮

| 按钮 | 作用 | 适用状态 | 说明 |
|---|---|---|---|
| 查看 | 查看批次详情 | 全部状态 | 只读查看 |
| 编辑 | 修改批次基础信息 | `AUDITING`、`EFFECTIVE` | 可编辑范围由状态控制 |
| 预上传 Code | 上传批次待用 Code | `AUDITING`、`EFFECTIVE` | 上传后必须校验 |
| 发放 | 开始批次发放 | 仅 `EFFECTIVE` | 触发实际发放动作 |
| 暂停 | 暂停批次发放 | 仅 `EFFECTIVE` | 中止当前发放 |
| 失效 | 结束批次并失效 | 仅 `EFFECTIVE` | 终止批次后续动作 |

### 6.3 批次详情按钮

| 按钮 | 作用 | 适用状态 | 说明 |
|---|---|---|---|
| 保存批次 | 保存批次基础信息 | `AUDITING`、`EFFECTIVE` | 保存草稿或已配置内容 |
| 保存并校验 Code | 保存并执行 Code 校验 | `AUDITING`、`EFFECTIVE` | 保存后进入校验流程 |
| 发放控制 | 进入发放、暂停、继续等控制动作 | 仅 `EFFECTIVE` | 由状态驱动 |
| 返回列表 | 返回批次列表区 | 全部状态 | 退出详情面板 |

## 7. 状态机设计

### 7.1 活动状态与批次入口关系

| 活动状态 | 批次管理入口 | 新建批次 | 预配置 | 发放 | 暂停 | 失效 |
|---|---|---|---|---|---|---|
| `AUDITING` 审批中 | 可用 | 可用 | 可用 | 不可用 | 不可用 | 不可用 |
| `EFFECTIVE` 生效中 | 可用 | 可用 | 可用 | 可用 | 可用 | 可用 |
| `DEACTIVATED` 已失效 | 不可用 | 不可用 | 不可用 | 不可用 | 不可用 | 不可用 |

### 7.2 批次状态说明

批次状态建议至少包含：
- 草稿
- 预配置中
- 已预配置
- 待发放
- 发放中
- 已暂停
- 已失效
- 已结束

### 7.3 批次状态流转

建议批次状态流转遵循以下逻辑：

1. 新建批次后进入 `草稿`
2. 完成基础信息和 Code 准备后进入 `预配置中`
3. 校验通过后进入 `已预配置`
4. 达到发放条件后进入 `待发放`
5. 执行发放后进入 `发放中`
6. 发放暂停后进入 `已暂停`
7. 批次被主动终止后进入 `已失效`
8. 发放完成且无后续动作时进入 `已结束`

说明：
- `已预配置` 表示准备工作完成，但尚未进入发放动作。
- `待发放` 表示已经具备发放条件，仅等待执行。
- `已结束` 表示批次生命周期自然结束，不一定代表失效。
- `已失效` 表示批次被主动终止，不再参与后续发放。

### 7.4 预配置定义

`预配置` 指在活动审批中提前完成批次的准备性信息维护，仅用于后续执行前的准备，不产生实际发放效果和状态流转结果。

`预配置` 可以包含：
- 新建批次草稿
- 编辑批次基础信息
- 填写发放前置参数
- 上传待用 Code
- 预览与校验

`预配置` 不包含：
- 发放
- 核销
- 失效
- 暂停
- 退券

## 8. 页面规则

1. 批次归属于某一个活动，不能脱离活动独立存在。
2. `AUDITING` 状态只允许查看与预配置。
3. `EFFECTIVE` 状态允许完整批次管理。
4. `DEACTIVATED` 状态不允许进入批次管理页操作。
5. `Code` 文件上传必须通过校验后才能进入下一步。
6. 发放、暂停、失效属于批次生命周期动作，仅在 `EFFECTIVE` 下开放。
7. 批次状态应与操作按钮严格绑定，避免出现状态和动作不一致。

## 9. 异常情况

| 场景 | 提示 | 处理方式 |
|---|---|---|
| 非法状态进入批次管理页 | 当前状态不可操作 | 阻止操作或只读展示 |
| Code 文件不合法 | 上传文件校验失败 | 阻止继续操作 |
| 批次信息缺失 | 批次信息不完整 | 提示补齐 |
| 发放时出现失败 | 发放失败，请重试 | 保留状态并记录失败原因 |
| 试图在 `AUDITING` 下执行发放 | 当前状态不可发放 | 阻止执行 |
| 试图在 `DEACTIVATED` 下编辑 | 当前状态不可编辑 | 阻止执行 |

## 10. 页面交互

1. 用户从活动详情页或列表页进入批次管理页。
2. 系统展示当前活动摘要与批次列表。
3. 用户可新建批次草稿或查看既有批次。
4. 在 `AUDITING` 状态下，用户只能进行批次预配置。
5. 在 `EFFECTIVE` 状态下，用户可执行完整批次管理动作。
6. 用户操作完成后，系统刷新批次列表和状态统计。
