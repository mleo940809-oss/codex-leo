# Weixin摇一摇 - 批次管理页设计稿

**文档版本**：V1.4  
**创建日期**：2026-05-10  
**适用范围**：Weixin摇一摇需求目录下的批次管理页  
**文档性质**：修订版，进一步收紧时间规则、预算语义、门店关联与通知配置边界

## 1. 设计目标

批次管理页用于管理单个商品券活动下的批次组信息，承载批次组的创建、查看、预配置、预算配置、门店关联、Code 管理、发放控制和状态管理。

本页只描述批次管理的页面能力，不展开后端接口实现细节。后端接口流转、异步回调和生命周期控制放入概设和流程图中体现。

## 2. 已确认的业务前提

1. 批次归属于某一个活动，不能脱离活动独立存在。
2. `AUDITING` 状态下允许进入批次管理页，但仅支持查看和预配置。
3. `SENDING` 是批次的发放态，进入后才允许发放相关操作。
4. `PAUSED`、`STOPPED`、`DEACTIVATED` 为批次终态或受限状态。
5. `Code` 文件上传归属批次管理页，不归属活动新增页、编辑页或修改页。
6. `预配置` 是页面内的准备性草稿/配置过程，不等于接口状态。
7. 预算配置是批次独立能力，不应与基础信息混写成一个笼统字段。
8. 门店关联仅在 `store_scope = SPECIFIC` 时开放。

## 3. 页面定位

- 一级模块：Weixin摇一摇
- 二级页面：批次管理页
- 页面职责：
  - 查看活动下的批次列表
  - 新建批次草稿
  - 维护批次基础信息
  - 配置批次时间规则、门店范围、预算和通知配置
  - 预上传 Code 并校验
  - 控制批次发放状态
  - 查看批次操作记录

## 4. 页面结构

建议批次管理页采用“活动摘要 + 批次列表 + 批次详情抽屉/面板 + 预算配置区 + 门店关联区 + Code 管理区 + 通知配置区 + 操作记录区”的结构：

1. 活动摘要区
2. 批次列表区
3. 批次详情区
4. 预算配置区
5. 门店关联区
6. Code 管理区
7. 通知配置区
8. 操作记录区

## 5. 字段设计

### 5.1 活动摘要区

活动摘要区用于展示当前活动的关键信息，便于批次操作时确认上下文。

| 字段 | 说明 | 展示方式 | 备注 |
|---|---|---|---|
| 商品券名称 | 当前活动名称 | 只读文本 | 用于确认活动上下文 |
| 商品券ID | 当前活动唯一标识 | 只读文本 | 用于定位活动 |
| 商品券类型 | 满减券 / 兑换券 | 只读文本 | 仅展示当前活动类型 |
| 活动状态 | 当前活动状态 | 状态标签 | 用于判断是否允许操作 |
| 优惠规则摘要 | 当前活动规则概述 | 只读文本 | 便于快速识别活动内容 |

### 5.2 批次列表区

批次列表区用于展示当前活动下的批次集合。

| 字段 | 说明 | 展示方式 | 备注 |
|---|---|---|---|
| 批次编号 | 批次唯一标识 | 只读文本 | 系统生成 |
| 批次名称 | 批次展示名称 | 只读文本 | 支持快速识别 |
| 批次状态 | 当前批次接口状态 | 状态标签 | 使用微信支付状态语义 |
| 可用开始时间 | 批次可用开始时间 | 时间文本 | 仅在常规时间规则模式下展示 |
| 可用结束时间 | 批次可用结束时间 | 时间文本 | 仅在常规时间规则模式下展示 |
| Code 总量 | 当前批次已上传 Code 总数 | 数值 | 对应已上传总数 |
| 可用 Code 数 | 当前可用 Code 数量 | 数值 | 对应剩余可用 Code 数量 |
| 已发放量 | 批次生命周期内已发放次数 | 数值 | 对应发放统计 |
| 创建人 | 批次创建人 | 只读文本 | 支持检索 |
| 最后修改人 | 最近一次修改批次的人 | 只读文本 | 支持检索 |
| 操作 | 批次行内操作 | 按钮组 | 按状态控制 |

说明：
- 列表展示的批次状态直接使用接口状态，不再使用“预配置完成”等内部抽象状态。
- 时间列仅表达当前批次采用的时间规则模式下的生效窗口，避免误解为所有规则都同时生效。

### 5.3 批次详情区

批次详情区用于展示和维护单个批次的完整信息。

#### 5.3.1 批次基础信息

| 字段 | 说明 | 是否可编辑 | 类型 | 备注 |
|---|---|---:|---|---|
| 批次名称 | 批次展示名称 | 是 | 文本 | 允许在可编辑状态下修改 |
| 批次编号 | 批次唯一标识 | 否 | 只读文本 | 系统生成 |
| 关联活动 | 所属活动 | 否 | 只读文本 | 与当前活动绑定 |
| 批次状态 | 当前批次接口状态 | 否 | 状态标签 | 由状态机驱动 |
| 备注 | 批次补充说明 | 是 | 文本 | 对应微信支付 `remark` |
| 门店范围 | 批次门店范围 | 是 | 枚举/配置项 | 对应 `store_scope` |

#### 5.3.2 时间规则区

时间规则区用于配置批次的可用时间约束，页面按“常规时间规则”与“指定时间规则”两种模式展示。

##### 5.3.2.1 常规时间规则

| 字段 | 说明 | 是否可编辑 | 类型 | 备注 |
|---|---|---:|---|---|
| 可用开始时间 | 批次可用开始时间 | 是 | 时间选择 | 与可用结束时间共同构成时间区间 |
| 可用结束时间 | 批次可用结束时间 | 是 | 时间选择 | 与可用开始时间共同构成时间区间 |
| 可用天数 | 券生效后 N 天内可用 | 是 | 正整数 | 对应 `available_days` |
| 领券后等待天数 | 领券后需等待 N 天才生效 | 是 | 正整数 | 对应 `wait_days_after_receive` |
| 每周固定可用时间 | 每周固定可用时间 | 是 | 周期配置 | 对应 `weekly_available_period` |

##### 5.3.2.2 指定时间规则

| 字段 | 说明 | 是否可编辑 | 类型 | 备注 |
|---|---|---:|---|---|
| 指定可用时间段 | 无规律时间段配置 | 是 | 时间段列表 | 对应 `irregular_available_period_list` |

##### 5.3.2.3 时间规则控制关系

- `可用天数` 与 `领券后等待天数` 必须同时填写，不能单独配置。
- `每周固定可用时间` 可与常规时间规则同时配置，多个条件同时满足时券才可用。
- `指定可用时间段` 与常规时间规则互斥，不能同时配置。
- `可用开始时间` 与 `可用结束时间` 仅在常规时间规则模式下使用，不适用于指定可用时间段模式。

#### 5.3.3 预算配置区

预算配置区用于展示和配置批次预算信息，预算能力单独拆分，不与基础信息混写。

| 字段 | 说明 | 是否可编辑 | 类型 | 备注 |
|---|---|---:|---|---|
| 批次总预算 | 批次总发放预算 | 是 | 数值配置 | 对应总预算 |
| 每日预算 | 批次每日发放预算 | 是 | 数值配置 | 选填配置项 |
| 每人限领 | 单用户限领次数 | 是 | 数值配置 | 选填配置项 |
| 预算配置状态 | 当前预算配置状态 | 否 | 状态标签 | 便于判断是否生效 |

说明：
- 预算配置是独立操作项，不再笼统地写成一个“发放预算”字段。
- 预算修改必须与基础信息、门店关联、Code 管理分离。
- 若本期只做展示不做编辑，应在 PRD 中明确为只读。

#### 5.3.4 门店关联区

| 字段 | 说明 | 是否可编辑 | 类型 | 备注 |
|---|---|---:|---|---|
| 门店关联状态 | 当前门店关联结果 | 否 | 状态标签 | 仅在 `store_scope = SPECIFIC` 时开放 |
| 已关联门店数 | 当前已关联门店数量 | 否 | 数值 | 只读展示 |
| 关联门店列表 | 已关联门店明细 | 是 | 列表/配置项 | 仅在 `SPECIFIC` 时开放 |

说明：
- 门店关联与批次基础信息分离。
- 当 `store_scope = ALL` 时，不展示门店关联操作。
- 当 `store_scope = SPECIFIC` 时，需支持批量关联和批量取消关联。

#### 5.3.5 统计信息区

| 字段 | 说明 | 展示方式 | 备注 |
|---|---|---|---|
| Code 总量 | 已上传 Code 总数 | 数值 | 只读展示 |
| 可用 Code 数 | 当前可用 Code 数量 | 数值 | 只读展示 |
| 已发放量 | 批次生命周期内已发放次数 | 数值 | 只读展示 |
| 当日发放量 | 今日已发放次数 | 数值 | 只读展示 |

### 5.4 Code 管理区

Code 管理区用于上传和校验批次待用 Code。

| 字段 | 说明 | 展示方式 | 备注 |
|---|---|---|---|
| Code 上传状态 | 当前 Code 文件处理状态 | 状态标签 | 如未上传、处理中、已校验、校验失败 |
| Code 文件名 | 已上传文件名 | 只读文本 | 用于识别文件 |
| Code 校验结果 | 文件合法性校验结果 | 结果标签 | 保存前需确认 |
| 上传时间 | 文件上传时间 | 时间文本 | 只读展示 |
| 校验时间 | 文件校验时间 | 时间文本 | 只读展示 |

### 5.5 通知配置区

| 字段 | 说明 | 是否可编辑 | 类型 | 备注 |
|---|---|---:|---|---|
| 通知配置 | 批次通知配置 | 是 | 配置项 | 对应微信支付通知配置能力 |

说明：
- 通知配置是一个配置对象，不应收缩成单个 AppID 字段。
- 若具体子字段在概设中再细化，应保持页面层为配置区而非单字段输入。

## 6. 按钮设计

### 6.1 顶部按钮

| 按钮 | 作用 | 适用状态 | 说明 |
|---|---|---|---|
| 新建批次 | 创建新的批次草稿 | `AUDITING`、`SENDING` | `AUDITING` 仅允许草稿和预配置 |
| 返回活动详情 | 返回活动详情页 | 全部状态 | 回到上级页面 |

### 6.2 批次列表行内按钮

| 按钮 | 作用 | 适用状态 | 说明 |
|---|---|---|---|
| 查看 | 查看批次详情 | 全部状态 | 只读查看 |
| 编辑 | 修改批次基础信息 | `AUDITING`、`SENDING`、`PAUSED` | 可编辑范围由状态控制 |
| 预算配置 | 修改批次预算 | `AUDITING`、`SENDING`、`PAUSED` | 预算独立配置，不与基础信息混写 |
| 门店关联 | 批量关联或取消关联门店 | `AUDITING`、`SENDING`、`PAUSED` | 仅在 `store_scope = SPECIFIC` 时开放 |
| 预上传 Code | 上传批次待用 Code | `AUDITING`、`SENDING` | 仅在 `coupon_code_mode = UPLOAD` 时开放，且批次未失效/未过期 |
| 发放 | 开始批次发放 | 仅 `SENDING` | 触发实际发放动作 |
| 暂停 | 暂停批次发放 | 仅 `SENDING` | 中止当前发放 |
| 失效 | 结束批次并失效 | `SENDING`、`PAUSED` | 终止批次后续动作 |

### 6.3 批次详情按钮

| 按钮 | 作用 | 适用状态 | 说明 |
|---|---|---|---|
| 保存批次 | 保存批次基础信息 | `AUDITING`、`SENDING`、`PAUSED` | 保存草稿或已配置内容 |
| 保存并校验 Code | 保存并执行 Code 校验 | `AUDITING`、`SENDING` | 保存后进入校验流程 |
| 保存预算 | 保存预算配置 | `AUDITING`、`SENDING`、`PAUSED` | 与批次基础信息分离 |
| 保存门店关联 | 保存门店关联结果 | `AUDITING`、`SENDING`、`PAUSED` | 仅在 `store_scope = SPECIFIC` 时开放 |
| 发放控制 | 进入发放、暂停、继续等控制动作 | `SENDING`、`PAUSED` | 由状态驱动 |
| 返回列表 | 返回批次列表区 | 全部状态 | 退出详情面板 |

## 7. 状态机设计

### 7.1 活动状态与批次入口关系

| 活动状态 | 批次管理入口 | 新建批次 | 预配置 | 发放 | 暂停 | 失效 |
|---|---|---|---|---|---|---|
| `AUDITING` 审批中 | 可用 | 可用 | 可用 | 不可用 | 不可用 | 不可用 |
| `EFFECTIVE` 生效中 | 可用 | 可用 | 可用 | 可用 | 可用 | 可用 |
| `DEACTIVATED` 已失效 | 不可用 | 不可用 | 不可用 | 不可用 | 不可用 | 不可用 |

### 7.2 批次接口状态说明

批次接口状态使用微信支付原生状态：
- `AUDITING`：审批中
- `SENDING`：发放中
- `PAUSED`：已暂停
- `STOPPED`：已停止，当前已到达结束时间
- `DEACTIVATED`：已失效

说明：
- 列表与详情中的“批次状态”以接口状态为准。
- 页面上的“草稿/预配置”只是编辑态，不作为已创建批次的正式状态展示。

### 7.3 页面预配置态

`预配置` 指在批次正式创建前或创建后审批完成前的准备性操作集合，仅用于页面上的配置与校验，不作为接口状态展示。

`预配置` 可以包含：
- 新建批次草稿
- 编辑批次基础信息
- 填写时间规则
- 配置预算
- 配置门店关联
- 上传待用 Code
- 预览与校验

`预配置` 不包含：
- 发放
- 核销
- 失效
- 暂停
- 退券

## 8. 页面规则

1. 批次归属于某一个活动，不能脱离活动独立存在。
2. `AUDITING` 状态只允许查看与预配置。
3. `EFFECTIVE` 状态允许完整批次管理。
4. `DEACTIVATED` 状态不允许进入批次管理页操作。
5. `Code` 文件上传必须通过校验后才能进入下一步。
6. 发放、暂停、失效属于批次生命周期动作，仅在 `SENDING` / `PAUSED` 等受控状态下开放。
7. 预算配置、门店关联、基础信息和 Code 管理必须分离，避免混写。
8. 批次状态应与操作按钮严格绑定，避免出现状态和动作不一致。
9. `pre-config` 仅是页面概念，不应作为接口状态或测试断言状态。

## 9. 异常情况

| 场景 | 提示 | 处理方式 |
|---|---|---|
| 非法状态进入批次管理页 | 当前状态不可操作 | 阻止操作或只读展示 |
| Code 文件不合法 | 上传文件校验失败 | 阻止继续操作 |
| 批次信息缺失 | 批次信息不完整 | 提示补齐 |
| 发放时出现失败 | 发放失败，请重试 | 保留状态并记录失败原因 |
| 试图在 `AUDITING` 下执行发放 | 当前状态不可发放 | 阻止执行 |
| 试图在 `DEACTIVATED` 下编辑 | 当前状态不可编辑 | 阻止执行 |

## 10. 页面交互

1. 用户从活动详情页或列表页进入批次管理页。
2. 系统展示当前活动摘要与批次列表。
3. 用户可新建批次草稿或查看既有批次。
4. 在 `AUDITING` 状态下，用户只能进行批次预配置。
5. 在 `SENDING` 状态下，用户可执行完整批次管理动作。
6. 用户操作完成后，系统刷新批次列表和状态统计。
