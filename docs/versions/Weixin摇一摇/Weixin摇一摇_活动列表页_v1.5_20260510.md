# Weixin摇一摇 - 活动列表页设计稿

**文档版本**：V1.5  
**创建日期**：2026-05-10  
**适用范围**：Weixin摇一摇 需求目录下的活动列表页  
**文档性质**：修订版，补充活动使用日期范围查询规则并收口列表汇总口径，明确覆盖窗口不代表连续可用

## 1. 设计目标

活动列表页作为 Weixin摇一摇 的统一入口，用于承载活动的检索、查看、编辑入口、批次入口和失效入口。

本页仅管理活动级能力，不展开批次详情和后端接口细节。批次的具体字段、Code 上传、预算、门店关联和发放控制统一进入批次管理页。为避免职责交叉，本页只承载活动层总览与入口分发，不承担展示层快照维护和批次层执行细节。活动详情页负责只读快照，批次管理页负责批次执行面。

## 2. 已确认的业务前提

1. 商品券类型仅支持两种：
   - 满减券
   - 兑换券
2. 使用模式固定为 `SINGLE`
3. 券 Code 分配模式固定为 `UPLOAD`
4. `SINGLE` 与 `UPLOAD` 均为系统固定属性，不作为列表筛选条件，也不在列表中作为可编辑字段展示
5. 活动支持草稿、审批中、生效中、已失效等状态
6. 编辑页用于草稿和审批中活动的生效前修订
7. 修改页用于生效中活动的低风险修改
8. 批次管理页仅在 `AUDITING` 与 `EFFECTIVE` 状态下开放，且能力边界不同

## 3. 页面定位

- 一级模块：Weixin摇一摇
- 二级页面：活动列表页
- 页面职责：
  - 展示活动列表
  - 提供筛选条件
  - 进入活动详情
  - 进入活动编辑页或修改页
  - 进入批次管理页
  - 执行活动失效

## 4. 查询条件规则

### 4.1 查询条件总览

| 字段 | 说明 | 查询方式 | 专业建议 |
|---|---|---|---|
| 商品券名称 | 活动名称关键字 | 模糊查询 | 保留为最常用检索条件，输入部分名称即可命中 |
| 商品券ID | 活动唯一标识 | 精确查询 | 定位单条活动的强条件，不建议模糊 |
| 商品券类型 | 满减券 / 兑换券 | 下拉单选 | 仅保留固定枚举，不允许自由输入 |
| 优惠范围 | 活动适用范围 | 下拉单选 / 树形选择 | 按系统配置字典展示，不建议自由输入 |
| 状态 | 活动当前状态 | 下拉单选 | 固定枚举，不使用“例如”式表达 |
| 创建人 | 活动创建人 | 模糊查询 | 按页面中保存的创建人名称模糊匹配即可 |
| 最后修改人 | 最近一次修改活动的人 | 模糊查询 | 按页面中保存的最后修改人名称模糊匹配即可 |
| 创建时间 | 活动创建时间 | 时间范围 | 使用起止时间筛选，建议默认本地时区 |
| 最后修改时间 | 活动最后修改时间 | 时间范围 | 使用起止时间筛选，建议默认本地时区 |
| 活动使用时间范围 | 当前活动下批次可用日期窗汇总窗口 | 日期范围 | 用于查找与查询范围存在部分重叠的活动 |

### 4.2 查询条件细则

#### 商品券名称
- 支持输入部分名称进行模糊查询
- 查询前建议去除首尾空格
- 不建议做精确匹配

#### 商品券ID
- 必须输入完整 ID 才能命中
- 不建议支持多值查询
- 建议保留复制后直接查询的能力

#### 商品券类型
- 仅允许选择 `满减券` 或 `兑换券`
- 后续如扩展新类型，再扩展枚举，不要先开放文本输入

#### 优惠范围
- 建议以系统配置字典或树形枚举方式选择
- 如果范围口径未完全稳定，优先展示范围摘要，不要开放自由输入

#### 状态
- 建议固定枚举：
  - 草稿
  - 审批中
  - 生效中
  - 已失效
- 不建议展示“例如”或“等”之类的非固定表达

#### 创建人 / 最后修改人
- 按页面中实际保存的名称做模糊匹配
- 不额外拆分姓名、账号、工号等字段
- 如果后台同时保存账号信息，可作为 hover 补充信息，不作为主查询条件

#### 创建时间 / 最后修改时间
- 使用时间范围选择器
- 起止时间建议都包含在查询范围内
- 建议默认采用本地时区 `Asia/Shanghai`
- 常用场景可补充快捷筛选：今天、最近 7 天、最近 30 天

#### 活动使用时间范围
- 查询目标是当前活动下所有**非草稿批次**的日期窗口
- 仅当活动下存在至少一个已配置可用日期窗的批次时，才参与命中
- 查询规则采用**部分重叠即可命中**
- 不要求查询范围与活动使用时间范围完全覆盖
- 适合作为按时间排查活动的筛选条件
- 列表展示的活动使用时间范围仅为覆盖窗口，不代表内部日期连续；若存在多个分散日期窗，页面仍只展示最早开始日期到最晚结束日期

### 4.3 活动使用时间范围的判断规则

#### 展示口径
- 活动使用时间范围 = 当前活动下所有非草稿批次的最早可用开始日期 ~ 最晚可用结束日期
- 若当前活动没有可用日期窗已确定的批次，则展示为 `--`
- 若当前活动下存在分散日期窗，列表仍仅展示覆盖窗口，不拆分显示多个区段

#### 查询口径
- 只要当前活动任一非草稿批次的日期窗与用户查询时间段存在重叠，即命中
- 查询口径采用日期窗重叠判断，不考虑周周期、离散时间段和秒级时间规则
- 部分重叠即可命中，不要求完全重叠
- 草稿批次不参与查询与汇总

#### 区间重叠规则
满足以下条件即可命中：
- 批次可用开始时间 `<=` 查询结束时间
- 且批次可用结束时间 `>=` 查询开始时间

## 5. 列表字段规则

### 5.1 列表字段总览

| 字段 | 说明 | 是否展示 | 展示建议 |
|---|---|---:|---|
| 商品券名称 | 活动展示名称 | 是 | 主展示列，超长省略，hover 显示完整名称，点击进入详情 |
| 商品券ID | 活动唯一标识 | 是 | 尽量完整展示，旁边提供复制能力 |
| 商品券类型 | 满减券 / 兑换券 | 是 | 使用标签展示，不建议纯文本 |
| 优惠范围 | 活动适用范围摘要 | 是 | 展示摘要，hover 显示完整内容 |
| 优惠规则摘要 | 面值 / 规则的简要展示 | 是 | 满减券显示“满X减Y”；兑换券显示“原价X / 兑换内容摘要” |
| 活动使用时间范围 | 当前活动下批次可用日期窗汇总窗口 | 可选 | 用于辅助判断活动跨度，可作为列表筛选辅助字段 |
| 状态 | 活动当前状态 | 是 | 使用状态标签展示，统一颜色体系 |
| 创建人 | 活动创建人 | 是 | 展示名称，必要时 hover 账号信息 |
| 最后修改人 | 最近一次修改活动的人 | 是 | 展示名称，必要时 hover 账号信息 |
| 创建时间 | 活动创建时间 | 是 | 默认展示到分钟，格式建议 `YYYY-MM-DD HH:mm` |
| 最后修改时间 | 活动最后修改时间 | 是 | 默认展示到分钟，格式建议 `YYYY-MM-DD HH:mm` |
| 批次数量 | 当前活动下的批次数量 | 可选 | 作为辅助列，不建议作为默认必显列 |
| 操作 | 行内按钮集合 | 是 | 保留稳定入口，避免每行按钮过多 |

### 5.2 字段展示细则

#### 商品券名称
- 作为列表第一主列
- 超长使用省略号，hover 显示完整名称
- 点击进入活动详情页

#### 商品券ID
- 尽量完整显示，不要过度截断
- 建议提供一键复制
- 适合作为排查和对账入口

#### 商品券类型
- 使用状态标签样式
- 满减券与兑换券的样式建议保持明显区分

#### 优惠范围
- 展示范围摘要即可，不要占用过宽空间
- 若范围较长，hover 展示完整内容

#### 优惠规则摘要
- 这是列表中最重要的业务信息列之一
- 满减券优先显示：
  - 满100减20
  - 满200减50
- 兑换券优先显示：
  - 原价99元 / 兑换内容摘要
  - 若组合较多，可追加“等N项”

#### 活动使用时间范围
  - 展示当前活动下非草稿批次的日期窗汇总结果
  - 展示格式建议为：`YYYY-MM-DD ~ YYYY-MM-DD`
  - 若没有可用批次日期窗，展示 `--`
- 仅作为辅助识别列，不替代批次管理页

#### 状态
- 必须以标签形式展示
- 建议统一颜色体系：
  - 草稿：灰色
  - 审批中：蓝色或橙色
  - 生效中：绿色
  - 已失效：灰色

#### 创建人 / 最后修改人
- 展示名称即可
- 如果系统同时保存账号或工号，可作为 hover 详情
- 不建议在列表中直接展开多个身份字段

#### 创建时间 / 最后修改时间
- 建议统一格式为 `YYYY-MM-DD HH:mm`
- 如果空间紧张，可默认展示到日期，hover 显示完整时间

## 6. 功能按钮

### 6.1 顶部按钮

| 按钮 | 作用 | 说明 |
|---|---|---|
| 新增活动 | 创建新的商品券活动 | 进入活动新增页 |

### 6.2 行内按钮

| 按钮 | 作用 | 适用状态 | 说明 |
|---|---|---|---|
| 查看 | 查看活动详情 | 全部状态 | 进入活动详情页 |
| 编辑 | 修改草稿或审批中活动 | `草稿`、`审批中` | 进入活动编辑页 |
| 修改 | 修改生效中活动 | `生效中` | 进入活动修改页 |
| 批次管理 | 进入活动批次管理页 | `审批中`、`生效中` | `审批中` 仅可查看和预配置；`生效中` 支持完整管理 |
| 失效 | 终止活动继续生效 | `生效中` | 失效后活动进入终态 |

### 6.3 按钮呈现建议

- 主按钮保留 `查看`
- `编辑 / 修改` 根据状态动态切换文案
- `批次管理` 与 `失效` 建议放入“更多”菜单，避免每行按钮过多
- 对于 `已失效` 状态，仅保留 `查看`

### 6.4 按钮点击规则

#### 新增活动
- 点击后进入活动新增页
- 不依赖当前列表选中行

#### 查看
- 点击后进入活动详情页
- 所有状态均可用

#### 编辑
- 仅 `草稿` 与 `审批中` 可用
- 点击后进入活动编辑页

#### 修改
- 仅 `生效中` 可用
- 点击后进入活动修改页

#### 批次管理
- 仅 `审批中` 与 `生效中` 可用
- `审批中` 进入后仅支持查看和预配置
- `生效中` 进入后支持完整管理

#### 失效
- 仅 `生效中` 可用
- 点击后需二次确认
- 确认后活动进入终态

## 7. 状态展示规则

| 状态 | 含义 | 展示建议 | 可用操作 |
|---|---|---|---|
| 草稿 | 已保存但未提交审核 | 灰色标签 | 查看、编辑 |
| 审批中 | 已提交审核，尚未进入执行态 | 蓝色或橙色标签 | 查看、编辑、批次管理（仅预配置） |
| 生效中 | 已正式生效 | 绿色标签 | 查看、修改、批次管理、失效 |
| 已失效 | 活动终态 | 灰色标签 | 仅查看 |

### 7.1 状态补充规则

1. `草稿` 允许编辑，不允许失效，不开放批次完整管理
2. `审批中` 允许进入批次管理页，但仅支持预配置和查看
3. `生效中` 允许修改低风险字段、进入批次完整管理、执行失效
4. `已失效` 仅允许查看

## 8. 业务规则

1. `使用模式` 固定为 `SINGLE`，不作为筛选条件，也不作为用户可编辑项
2. `券 Code 分配模式` 固定为 `UPLOAD`，不作为筛选条件，也不作为用户可编辑项
3. 活动仅在 `草稿` 与 `审批中` 状态允许进入编辑页
4. 活动仅在 `生效中` 状态允许进入修改页
5. 活动仅在 `审批中` 与 `生效中` 状态允许进入批次管理页
6. `草稿` 不开放批次完整管理
7. `已失效` 不开放编辑、修改、批次管理和失效操作
8. 活动失效后，不再允许继续发放新的券
9. 活动使用时间范围仅以非草稿批次参与汇总与查询，且仅按日期窗口径计算

## 9. 异常情况

| 场景 | 提示 | 处理方式 |
|---|---|---|
| 非 `草稿` / `审批中` 状态点击编辑 | 当前状态不可编辑 | 按钮置灰或隐藏 |
| 非 `生效中` 状态点击修改 | 当前状态不可修改 | 按钮置灰或隐藏 |
| `草稿` 点击批次管理 | 当前状态仅允许编辑活动内容 | 按钮置灰或隐藏 |
| `已失效` 点击批次管理 | 当前状态不可操作 | 按钮置灰或隐藏 |
| 无权限用户访问操作 | 无操作权限 | 按权限隐藏或提示 |
| 查询无结果 | 未找到符合条件的数据 | 展示空状态 |
| 活动无可用批次日期窗 | 当前活动暂无可查询的使用时间范围 | 活动使用时间范围展示为 `--` |

## 10. 页面交互

1. 用户进入活动列表页，系统默认展示活动列表数据。
2. 用户可通过查询条件检索活动。
3. 用户点击 `新增活动` 进入新增页。
4. 用户点击 `查看` 进入活动详情页。
5. 用户点击 `编辑` 进入编辑页。
6. 用户点击 `修改` 进入修改页。
7. 用户点击 `批次管理` 进入该活动的批次管理页。
8. 用户点击 `失效` 后，系统弹出二次确认，确认后执行失效流程。
