# 流程执行技能附录

## 1. 使用原则

本附录仅描述各流程节点的执行技能路由，不替代主流程规范。

- 主流程规范负责定义节点、责任、审批、时限和交付边界。
- 本附录负责定义到达节点后应采用的技能顺序和执行意图。
- 如技能名称、工具或执行方式发生变化，本附录先行更新，主流程不随工具实现层变化频繁调整。

## 2. 节点技能路由

### 2.1 需求受理
- 主 skill：`notion:notion-knowledge-capture`
- 辅 skill：`slack:slack-reply-drafting`
- 任务：将原始需求整理为结构化登记内容，补全来源、提出人、业务负责人、背景、诉求、时效，并形成登记单。

### 2.2 需求初筛与分级
- 主 skill：`superpowers:brainstorming`
- 辅 skill：`superpowers:systematic-debugging`
- 任务：拆解问题边界，判断价值、紧急度、重复性和可行性，输出分级与路径建议。

### 2.3 需求分析
- 主 skill：`superpowers:writing-plans`
- 辅 skill：`notion:notion-spec-to-implementation`
- 任务：将需求拆成问题定义、目标定义、影响范围和约束条件，并形成后续执行可用的分析结论。

### 2.4 方案设计与评审
- 主 skill：`superpowers:receiving-code-review`
- 辅 skill：`superpowers:brainstorming`
- 任务：评审业务、技术、测试、设计和数据反馈，对比备选方案并形成明确结论。

### 2.5 需求确认与冻结
- 主 skill：`superpowers:verification-before-completion`
- 辅 skill：`superpowers:executing-plans`
- 任务：核对范围、字段、规则、异常场景和验收标准，确认冻结基线是否可进入后续执行。

### 2.6 需求交付包输出
- 主 skill：`documents:documents`
- 辅 skill：`notion:notion-knowledge-capture`
- 任务：生成标准化交付文档和附件，完成编号、归档和知识沉淀。

### 2.7 紧急需求特批通道
- 主 skill：`superpowers:systematic-debugging`
- 辅 skill：`superpowers:receiving-code-review`
- 任务：快速定位紧急问题根因，判断是否属于特批场景，并评估风险和处理路径。

### 2.8 变更管理
- 主 skill：`superpowers:receiving-code-review`
- 辅 skill：`superpowers:writing-plans`
- 任务：审查变更影响、评估成本与风险，并形成可执行修订方案。

### 2.9 时限与升级
- 主 skill：`superpowers:executing-plans`
- 辅 skill：`superpowers:verification-before-completion`
- 任务：按节点时限推进、检查超时、触发提醒和升级。

### 2.10 决策与冲突裁定
- 主 skill：`superpowers:receiving-code-review`
- 辅 skill：`superpowers:brainstorming`
- 任务：收集冲突意见，判断裁定边界并给出最终决策。

### 2.11 统一交付标准
- 主 skill：`superpowers:verification-before-completion`
- 辅 skill：`documents:documents`
- 任务：检查交付物齐套性、版本一致性和可交付性。

### 2.12 考核与复盘
- 主 skill：`superpowers:systematic-debugging`
- 辅 skill：`notion:notion-knowledge-capture`
- 任务：收集卡点、分析根因、沉淀改进项和复盘结论。

### 2.13 附则写作
- 主 skill：`superpowers:writing-skills`
- 辅 skill：`notion:notion-knowledge-capture`
- 任务：将制度表达写成无歧义、可执行、可检索的规范语言。

### 2.14 版本管理
- 主 skill：`superpowers:finishing-a-development-branch`
- 辅 skill：`verification-before-completion`
- 任务：完成版本收口、历史留存、正式发布前检查和回滚准备。

## 4. 标准PRD模板章节技能路由

本节适用于 [standard-prd-template.md](/E:/Codex/New_rules/docs/standard-prd-template.md)。  
该模板用于正式评审、冻结与交付阶段，目标是输出高颗粒度、可验收、可回溯的正式 PRD。

| 章节 | 主 skill | 辅 skill | 具体工作 |
|---|---|---|---|
| 0. 模板使用规则 | `superpowers:writing-skills` | `superpowers:receiving-code-review` | 定义前期探索模板与正式交付模板的切换边界、禁止混用规则和版本留档要求。 |
| 1. 封面信息 | `documents:documents` | `notion:notion-knowledge-capture` | 收集项目、产品、版本、编写人、部门等元信息，形成正式封面。 |
| 2. 修订记录 | `documents:documents` | `superpowers:verification-before-completion` | 记录版本、时间、修订内容、修订人与审核人，保持版本链可追溯。 |
| 3. 需求列表 | `notion:notion-knowledge-capture` | `documents:documents` | 收口 Epic / User Story / 提出部门 / 发布版本，形成需求总索引。 |
| 1. 产品概述 | `superpowers:brainstorming` | `superpowers:writing-plans` | 收敛业务背景、目标用户、产品目标、架构、功能架构和场景。 |
| 1.4 应用架构 | `figma:figma-generate-design` | `superpowers:brainstorming` | 输出应用架构图，并附可编辑源文件、系统关系和数据流向。 |
| 1.5.1 功能清单（思维导图的形式） | `figma:figma-generate-design` | `superpowers:writing-plans` | 输出思维导图图稿，并保证功能点与后续功能需求一致。 |
| 1.5.3 整体流程图 | `figma:figma-generate-design` | `superpowers:verification-before-completion` | 输出泳道图 / 流程图图稿，并标明角色、判断、异常和输出结果。 |
| 2. 功能需求 | `superpowers:writing-plans` | `superpowers:verification-before-completion` | 按功能编码拆解到一级模块、页面级功能点、动作级、字段级、规则级和异常级。 |
| 2.1 角色用例图 | `figma:figma-generate-design` | `superpowers:brainstorming` | 输出功能模块层级的角色用例图，并提供可编辑源文件。 |
| 2.1.1.2.1 角色用例图 | `figma:figma-generate-design` | `superpowers:brainstorming` | 输出 User Story 级角色用例图，并标明中心平台 / 外部系统 / 中台能力。 |
| 2.1.1.2.2 产品流程图 | `figma:figma-generate-design` | `superpowers:verification-before-completion` | 输出主流程、分支流程和异常流程图，并保留可编辑源文件。 |
| 2.1-2.1.1.6.4 细粒度功能块 | `frontend-design` / `figma:figma-generate-design` / `figma:figma-implement-design` | `superpowers:verification-before-completion` | 对页面、交互、原型和动作级说明进行高保真输出与一致性验证。 |
| 2.1.1.6 原型图 / UI 界面 | `frontend-design` | `figma:figma-generate-design` / `figma:figma-implement-design` | 输出页面级预览图、可编辑源文件和 HTML 高保真原型，确保图稿与说明一致。 |
| 3. 集成需求 | `superpowers:systematic-debugging` | `superpowers:writing-plans` | 梳理第三方、中台、接口、失败补偿、状态流转和依赖关系。 |
| 4. 非功能性需求 | `superpowers:verification-before-completion` | `superpowers:systematic-debugging` | 约束性能、安全、监控、运行环境、埋点和其他非功能要求。 |
| 5. 数据治理-逻辑模型 | `spreadsheets:Spreadsheets` | `superpowers:systematic-debugging` | 建模业务对象、逻辑实体、属性关系、主外键和数据来源。 |
| 6. 用户测试用例 | `superpowers:verification-before-completion` | `superpowers:receiving-code-review` | 将功能点、规则、状态流转和异常转成可执行测试用例。 |
| 7. 附件一 确认书 | `documents:documents` | `superpowers:verification-before-completion` | 生成正式签核、确认意见和最终交付留档。 |

## 3. PRD章节技能路由

本节适用于 [PRD工作流复用模板](/E:/Codex/New_rules/docs/PRD工作流复用模板.md) 的主章节。  
其中 `5.1`、`5.2`、`5.3` 这类重复功能模块段落，统一沿用“功能需求”的技能组合，不单独拆分技能类型；`5.1.11` 及其重复段落的原型一致性矩阵也按同类路由执行。

| PRD章节 | 主 skill | 辅 skill | 具体工作 |
|---|---|---|---|
| 1. 文档信息 | `documents:documents` | `notion:notion-knowledge-capture` | 收集文档元信息、项目/模块/负责人、评审状态和编写日期，形成可检索的正式抬头。 |
| 2. 修订记录 | `documents:documents` | `superpowers:verification-before-completion` | 记录版本演进、修订原因、修订人和时间，确保版本链可追踪。 |
| 3. 需求申请信息 | `notion:notion-knowledge-capture` | `documents:documents` | 收口需求来源、Epic / Story、提出部门和计划版本，避免信息散落。 |
| 4. 产品概述 | `superpowers:brainstorming` | `superpowers:writing-plans` | 组织背景、目标、架构、场景和边界，先定义问题再展开方案。 |
| 5. 功能需求 | `superpowers:writing-plans` | `superpowers:verification-before-completion` | 逐一级模块和页面级功能点拆解描述、规则、异常和字段，形成可执行正文。 |
| 6. 集成需求 | `superpowers:systematic-debugging` | `superpowers:writing-plans` | 梳理接口、流程、失败处理和依赖关系，识别集成风险与约束。 |
| 7. 非功能性需求 | `superpowers:verification-before-completion` | `superpowers:systematic-debugging` | 核对性能、安全、监控、运行环境和埋点要求，避免漏项。 |
| 8. 数据治理 | `superpowers:systematic-debugging` | `documents:documents` | 明确逻辑模型、业务对象、属性口径和数据边界。 |
| 9. 测试用例 | `superpowers:verification-before-completion` | `superpowers:receiving-code-review` | 把功能点、规则和异常转成可验证用例，检查可测性和覆盖率。 |
| 10. 评审与确认 | `superpowers:receiving-code-review` | `superpowers:verification-before-completion` | 汇总评审结论、签核和交付包，确认是否通过并可进入冻结。 |
| 10.3 原型交互验收 | `figma:figma-generate-design` | `superpowers:verification-before-completion` | 对活链接原型进行实际手测，验证主路径、分支、异常、权限和收尾动作。 |
| 10.4 需求交付包输出 | `documents` + `notion:notion-knowledge-capture` | `superpowers:verification-before-completion` | 必须沉淀为可复用交付资产，并和原型交互验收结果一起冻结。 |
| 11. 填写建议 | `superpowers:writing-skills` | `documents:documents` | 规范填写口径、章节稳定性和复用建议，保证后续版本对比一致。 |
